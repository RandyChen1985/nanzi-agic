1 一、平台概览与基础环境 (Overview & Environment)

1.1 推荐运行依赖与系统要求

平台经过严密工程设计，建议在以下标准技术栈环境下部署运行：

  • 操作系统：Linux (Ubuntu 20.04+ / Debian 11+ / CentOS 7+)、macOS (Apple Silicon / Intel)、Windows (WSL2)。
  • Python 运行时：Python 3.11（推荐使用 uv 极速虚拟环境管理器，严禁使用 3.10 或 3.12+ 专有语法）。
  • Node.js 运行时：Node.js 18.18+ / 20.x（用于前端 Vite 7 + Vue 3 编译与构建）。
  • 缓存与向量搜索引擎：Redis Stack Server 7.x+（必须包含 RediSearch 模块，不能使用裸 Redis 6.x）。
  • 主数据库：MySQL 8.0+ 或 PostgreSQL 14+（双库均提供增量迁移支持）。
  • 安全沙箱环境 (Docker)：推荐主机安装 Docker 20.10+。
⚠️ 核心部署安全原则（平台容器化部署场景）： 当 NanZi 平台自身部署在 Docker 容器内运行时，强烈建议安全沙箱配置走 docker 策略（启动主容器时挂载宿主机套接字 -v /var/run/docker.sock:/var/run/docker.sock）。若使用 local 策略，所有 Agent 执行的 Shell 脚本和命令都会在平台后端主服务容器内裸奔执行；而配置为 docker 沙箱策略后，平台会为每位用户在宿主机 Docker 引擎上独立启动纯净隔离的沙箱子容器，实现操作系统级安全防护！

1.2 本地与服务器快速启动指南 (dev.sh)

平台根目录下提供了全自动化前台与后台管理脚本 ./dev.sh：

Bash (dev.sh 启动命令)
# 1. 前台调试启动 (实时查看 Vite 前端编译与 FastAPI 访问日志，Ctrl+C 退出)
./dev.sh

# 2. 后台常驻启动 (Daemon 守护模式，关闭 SSH 终端依然稳健运行)
./dev.sh -d
# 或
./dev.sh --daemon

dev.sh 核心特性：自动释放被占用的旧端口、自动校验 package.json 校验和并在依赖变更时自动执行 npm install、动态读取 .env 端口配置（默认 8001）、自动触发 Vite 编译并将产物交由 FastAPI 静态托管。

1.4 小白高频问题与排查 Q&A

Q 为什么强烈要求使用 Python 3.11？系统自带的 Python 3.8 或 3.12 可以吗？ ▼
不可以。
  • Python 3.8/3.9 缺少平台所需的现代异步特性与类型系统（如 asyncio.TaskGroup、Pydantic 2 新语法）；
  • Python 3.12+ 移除或改变了部分底层标准库 API，且部分 AI/数据分析第三方 C 扩展依赖（如部分旧版本轮子包）在 3.12+ 上可能缺少 pre-built wheels 导致本地编译报错。
推荐做法：使用 uv 极速安装隔离的 3.11 环境： uv python install 3.11 && uv venv --python 3.11 .venv && source .venv/bin/activate
Q ./dev.sh 和 ./dev.sh -d 有什么区别？关掉终端窗口后服务会停止吗？ ▼
  • ./dev.sh (前台模式)：所有编译日志、FastAPI 访问日志都会实时打印在当前终端窗口中。一旦关闭终端窗口或按 Ctrl+C，服务会随之终止。适合本地开发与排查问题。
  • ./dev.sh -d (后台常驻模式)：服务会通过 nohup 在后台静默运行。即使关闭 SSH 终端窗口或断开网络，服务依然会在后台持续运行。适合长期测试或部署在云服务器上。
Q .env 配置文件在哪里？我修改了配置为什么不生效？ ▼
项目根目录下有模板文件 .env.example，首次使用需复制一份命名为 .env：cp .env.example .env。
重要逻辑：.env 中的环境变量仅在服务启动初始化阶段由 Python 读取。修改 .env 后必须重启服务（重新执行 ./dev.sh）才能生效。

2 二、智能助手与交互画布 (Smart Assistant & Canvas)

2.1 核心逻辑：智能助手与交互画布的协同机制

智能助手采用左右分栏、双向协同的工作流：

  • 左侧（对话与控制区）：负责智能体的自然语言交流、思考过程（Thinking CoT）展开折叠、工具调用状态跟踪、AI 提问交互卡片确认及 TODO 任务清单分步跟踪；
  • 右侧（交互画布 Canvas）：当智能体生成前端代码（HTML/JS/Vue）、数据图表、Markdown 技术方案、或通过工具产出交付物文件时，右侧画布会自动呼出并实时渲染工件（Artifact）。用户可以在画布中直接编辑代码、切换设备预览尺寸，并一键保存写回沙箱工作区。

2.2 聊天输入框全能工具箱

特性功能 触发与操作方式 核心价值与应用场景
多模态附件与截图 点击附件图标 / 剪贴板按 Ctrl+V (Mac Cmd+V) 直接贴入图片/文档，智能体自动调用多模态 Vision 模型进行图像理解与 OCR 识别。
@ 专家智能体直选 输入框输入 @ 呼出下拉列表 指定本轮对话由专属专家（如 @ChatBI分析师、@代码审计员）接管，享受专属 System Prompt。
/ 快捷指令库 输入框输入 / 呼出面板 快速调用预设 Prompt 模板（如数据集快捷分析、代码评审模板），一键填充发送。
技能与 MCP 挂载 点击输入框底部的 Skill / MCP 按钮 动态为当前会话勾选挂载领域专精技能包与外部工具服务，无需全局更改 Prompt。

2.3 输入框浮标：Token 水位线、压缩日志与沙箱卡片

聊天输入框右上角集成了多功能自适应状态浮标：

  • Token 水位线与健康度：动态环形进度条展示当前会话已占用的 Token 数与上限占比，自适应显示 🟢使用正常 / 🟡接近上限 / 🔴已达上限。
  • 上下文压缩时间线 (Compaction Timeline)：当多轮长会话触发平台两阶段压缩时，浮标提供时间线弹窗入口，可查看各轮次提炼的高浓度摘要与 Token 节省比例。
  • 沙箱运行环境卡片：直观显示当前生效策略（Local/Docker/E2B/SSH）；在 docker 策略下展示容器实时运行状态、Container ID、秒级递增运行时长及【启动容器 / 重新连接】按钮。

2.4 控制台：排版主题、单/多轮记忆与四维性能分析

  • 5+ 套精美排版主题：极简白、优雅蓝、护眼绿、暗黑极客等，支持一键切换适合阅读或截图的渲染风格；
  • 单轮 / 多轮记忆模式：支持切换单轮独立测试或多轮连续上下文对话；
  • 模型调用四维 Token 拆解：精确拆解 System Prompt、Tools Schema、Memory/History 与 Current Turn 的 Token 分项占比图，并提供首字响应延迟 (TTFT) 与总耗时指标。

2.5 浏览器自动化会话与实时投屏接管

智能体调用 browser_* 工具系列（打开网页、滚动、点击、表单输入、截图）时，在后台保持无头浏览器会话。右侧画布支持展开【浏览器面板】，实时查看 Agent 操作的页面截图，支持人工直接点击、输入网址实现人机协同接管。

2.6 常见交互排查 Q&A

Q 聊天记录中出现的“自动整理线”是什么意思？我的聊天记录被删除了吗？ ▼
没有被删除。 大模型单次会话所能接收的上下文长度是有上限的（默认 64k Tokens）。如果多轮长对话的历史记录太长，会导致模型报错或费用暴增。
当逼近预算上限时，系统会自动启动两阶段智能溢出压缩：将较早轮次的历史对话提炼为结构化关键摘录，并在界面插入一条「自动整理线」。新一轮对话将基于这个高浓度摘要继续进行，既保留了前文核心信息，又大幅降低了 Token 消耗。

3 三、智能体开发平台 (Agent Development Platform)

3.1 核心逻辑：智能体、技能 (Skill) 与 MCP 工具的区别与联系

graph TD
    Agent["🤖 智能体 (Agent)
大脑与核心角色，定义 Prompt 与人格"] --> Skill["📚 技能 (Skill)
专业知识与工作流指导手册 (Markdown)"]
    Agent --> MCP["🛠️ MCP 工具 (Tool)

  • 智能体 (Agent)：拥有独立人设、目标和决策逻辑的 AI 角色实体；
  • 技能 (Skill)：传授给智能体的领域专业工作流知识（以标准 SKILL.md 形式存储），告诉智能体“遇到这类任务应该分几步做、遵循什么规范”；
  • MCP 工具 (Model Context Protocol)：智能体用来与外界交互的可执行代码接口（如查询天气、执行 Python 脚本、操作浏览器等）。

3.2 智能体构建五大要素与子代理架构 (Subagents Architecture)

平台主编排采用 Master-Subagent 架构，解决复杂跨领域任务中的上下文遗忘与单点崩溃问题：

sequenceDiagram
    autonumber
    actor User as 用户 (User)
    participant Master as 👑 主编排智能体 (Master Agent)
    participant Sub1 as 🔍 检索专家子代理 (Research Subagent)
    participant Sub2 as 💻 编程专家子代理 (Coding Subagent)

    User->>Master: 提出综合性复杂需求
    Master->>Master: 任务拆解与执行规划 (Task Decomposition)
  
    Master->>Sub1: 派发检索任务 (invoke_subagent)
    Sub1->>Sub1: 深度搜索与数据清洗 (独立上下文)
    Sub1-->>Master: 仅返回结构化调研摘要结论

    Master->>Sub2: 派发代码编写与沙箱验证任务
    Sub2->>Sub2: 编写并执行测试 (独立沙箱)
    Sub2-->>Master: 仅返回最终代码工件与验证状态

    Master-->>User: 汇总交付高水准最终方案

3.3 技能工作台与平台审核机制

技能包采用标准的 YAML Frontmatter + Markdown 指令正文 规范。智能体在每轮对话开始时，根据用户输入的语义意图与技能描述进行语义相似度快速匹配并按需加载，节约 90% 以上上下文消耗。

3.4 MCP 工具集规范与 FastMCP 网关

  • STDIO MCP (标准输入输出)：适合本地命令或脚手架（如 Postgres/Puppeteer MCP）；
  • SSE MCP (HTTP 长连接)：适合跨主机、跨网络的分布式微服务；
  • In-Container FastMCP 网关：Docker 沙箱容器内自动拉起专有 FastMCP 网关，Bash/Read/Write 均以标准 MCP Tool 方式暴露，容器异常完全不影响主服务。

3.7 任务调度台 (Task Center) 与 Cron 定时任务

支持创建按 Cron 表达式周期性自动运行的智能体任务（如每日早上 9:00 自动生成业务报表并推送到企微群）。通俗 Cron 表达式速查：

  • */10 * * * *：每 10 分钟执行一次；
  • 0 * * * *：每小时整点执行一次；
  • 0 9 * * *：每天早上 9:00 执行一次；
  • 0 9 * * 1-5：每周一至周五早上 9:00 执行一次（工作日报）。

3.9 智能体排查 Q&A

Q 我在技能工作台写了一个新技能，为什么智能体对话时好像没有使用？ ▼
排查步骤：
  1. 检查技能是否已通过管理员审核并处于启用状态；
  2. 检查技能的 YAML Frontmatter 描述（description）是否准确清晰。大模型是根据你的 description 语义判断何时调起该技能的，若描述过于模糊，大模型可能无法命中。

4 四、ChatBI 开发平台 (ChatBI Platform)

4.1 核心逻辑：ChatBI 是如何安全查询企业数据的？

很多企业用户担心“用大模型查数据库会不会泄露机密业务数据”。平台的实现逻辑绝对安全，严守数据不出域原则：

flowchart TD
    UserQuery["用户自然语言提问
（例如：上月华东区销售额是多少？）"] --> Step1["① 提取元数据字典与字段别名
（仅包含表结构，绝无真实业务数据！）"]
    Step1 --> Step2["② 发送给 LLM 生成只读 SQL"]
    Step2 --> Step3["③ 平台本地只读连接池执行 SQL"]
    Step3 --> Step4["④ 在本地将统计结果绘制为图表返回给前端"]
  • 只传 Schema，不传数据：发送给大模型的只有数据表结构、字段说明和几条案例，真实数据记录绝不会发送给大模型；
  • 纯只读安全执行：生成的 SQL 仅在平台本地数据库连接池中执行，并强制拦截一切写操作（INSERT/UPDATE/DELETE/DROP 均直接拦截）。

4.2 元数据同步与业务语义字典标注 (Metadata Management)

元数据管理是大模型理解企业底层数仓的“业务翻译官”：

  • 数据集 (Dataset) 划分：按业务域划分（如电商交易、财务账单），隔离无关表，防止大模型混淆并节省 80% Token；
  • 字段属性治理：明确标注字段类型、维度（Dimension，用于分组过滤）与度量（Metric，用于求和/均值），明确主外键关联关系确保 JOIN 100% 准确；
  • 业务枚举字典映射：针对 pay_status 等字段配置枚举（0=未支付, 1=已支付, 2=已退款），大模型查退单时精准命中 pay_status = 2；
  • AI 辅助一键智能标注：自动根据字段英文单词推荐地道中文名，支持一键保存。

4.4 ChatBI 常见排查 Q&A

Q 用户提问“上周五的 GMV 是多少”，大模型怎么知道“上周五”是哪一天？ ▼
平台通过 agentscope_inject_runtime_state 机制，在每次生成 SQL 前向大模型注入了当前精确北京时间、当前日期与星期几；大模型会自动推算出“上周五”的具体日期（如 2026-08-14），并生成对应的日期过滤条件。
Q 数据库里有敏感表（如员工薪资表），如何防止被 ChatBI 查到？ ▼
在【元数据管理】中，找到对应的敏感表，将其状态切换为 禁用 / 隐藏。隐藏后的表结构绝不会被放入 Prompt 发送给大模型，大模型完全不知道该表的存在，从而实现物理级权限隔离。

5 五、知识库开发平台 (Knowledge Base Platform)

5.1 核心逻辑：RAG 知识库检索与文档切片原理

  • 构建期（文档切片与向量化）：上传 PDF/Word 等文档 -> 智能切片为段落 (Chunk) -> 调用 Embedding 模型转换为多维向量 -> 存入 RediSearch 向量库；
  • 检索期（语义匹配与回答生成）：提问转向量 -> 检索最相似的 Top-K 文档片段 -> 作为参考依据注入 Prompt -> 大模型生成有据可依的回答。

5.2 知识库创建与 RAGFlow 引擎对接

支持解析 PDF、Word (.docx)、Excel、Markdown、TXT 等格式；集成 RAGFlow 深度文档理解引擎，支持智能表格抽取与多模态图表解析。

5.3 混合检索 (Hybrid Search) 与重排序 (Rerank) 调优

  • 混合检索：结合向量语义相似度（Dense Retrieval）与 BM25 关键词全文匹配（Sparse Retrieval）；
  • 重排序 (Rerank)：接入 BGE-Reranker 等重排模型，对初筛结果进行二次精排打分，大幅减少 AI 幻觉。

5.5 知识库排查 Q&A

Q 为什么我明明上传了包含答案的文档，提问时 AI 却说“在知识库中未找到相关内容”？ ▼
排查与解决：
  1. 切片尚未完成：检查文档状态是否为 解析完成；
  2. 提问词差异过大：进入【检索测试】页面输入问题进行召回调试，观察相似度得分是否低于系统设置的阈值；
  3. 分块被切断：若关键信息恰好被跨段切分，可适当调大分块大小（Chunk Size）并开启重叠长度（Overlap）。

6 六、日志与 Token 分析 (Logs & Token Analytics)

6.1 什么是 Token 与计费原理？

Token 是大模型处理文本的基本单位。中文通常 1 个汉字 ≈ 1 ~ 2 个 Tokens；英文通常 1 个单词 ≈ 1.3 个 Tokens。平台精准区分 Prompt Tokens（输入） 与 Completion Tokens（输出），支持配置模型单价并核算企业成本报表。

6.2 审计日志 (Audit Logs) 与操作追溯

完整记录平台所有敏感运维动作（用户管理、角色赋权、系统配置修改、数据源变动等），记录操作人、来源 IP、时间戳与前后变更 Diff。

6.3 聊天日志 (Chat Logs) 与复盘诊断

管理员可多维度检索全平台会话记录，查看完整的上下文压缩日志、模型 Token 消耗及工具调用细节，并可“一键将优质问答采纳为 Few-Shot 案例”。

6.5 日志分析 Q&A

Q 审计日志和聊天日志有什么区别？ ▼
  • 审计日志：关注系统安全与权限变更（如“张三在 10:00 修改了管理员角色权限”）；
  • 聊天日志：关注AI 对话内容与消耗诊断（如“李四向智能体提问了一段 Python 代码，耗费了 1200 Tokens”）。

7 七、系统管理与配置 (System Management & Configuration)

7.1 用户与双层权限架构 (RBAC)

  • 菜单权限 (menu:*)：控制左侧侧边栏页面可见性；
  • 元素/功能级权限 (element:*)：控制页面内创建、编辑、删除、发布、审核等敏感操作权限（如 element:skills:admin）；
  • API Key：每个用户拥有唯一 api_key，外部系统通过 Authorization: Bearer <KEY> 调用开放 API。

7.2 模型注册与提供商管理 (Model Registry)

  • 主流厂商生态：OpenAI、DeepSeek、Qwen（百炼/通义）、Volcengine Ark（火山引擎/豆包）、SiliconFlow、Moonshot、ZhipuAI 等，及本地 Ollama / vLLM / Xinference；
  • Base URL 智能识别：自动识别已有版本号的 URL，避免错误拼接 /v1 导致 404；
  • 深度思考兼容层：内建 ThinkingToolChoiceCompatAgent，完美兼容 DeepSeek-R1 / QwQ 等思考模型的 <think> 解析与工具调用。

7.3 多策略安全沙箱与 Docker 镜像预构建

沙箱策略 隔离级别 运行位置 适用场景与核心说明
local 进程级 本机 / 宿主机主进程 个人本地开发、单机快速体验。在 Docker 容器化部署时不建议使用。
docker (推荐) 容器级 本地 Docker 引擎 企业生产推荐。为每位用户分配独立容器与工作区，隔离 Bash 与文件操作。
e2b 微虚拟机 E2B 云端沙箱 无本地 Docker 资源的云原生架构，需配置 E2B API Key。
ssh 远程主机 独立远程服务器 专用高性能计算节点。
